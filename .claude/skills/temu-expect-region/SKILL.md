# temu-expect-region — 期望到货区域批量设为义乌

改数据任务（唯一改数据的入口）：把当前店铺全部 JIT/定制品的「当前期望到货区域」收敛为**义乌**。
幂等：已是义乌的商品再设一遍无副作用。2026-10-15 在 store-d 全流程实测通过。

## 授权门禁（红线）

- 仅当**用户在对话中明确要求**或**工作台卡片点击**时才执行；报告必须如实记录点了什么。
- 全程不点「按勾选同步」「忆托ERP同步」，不碰任何验证码（出现滑块 → 立即停手报告）。
- 开始前先截图右上角**账号名**，报告写明操作的是哪家店；跑错店的代价不可逆。

## 流程（坐标一律实时 OCR/裁剪定位，下方数字仅为 2560x1400 参考值）

### 1. 进入页面

```
导航 https://agentseller.temu.com/stock/fully-mgt/sale-manage/main（销售管理·全球）
→ OCR 搜「期望到货区域设置」按钮（批量申请备货右侧，参考 (716,1162)）→ 点击 → sleep 5 截图
```

弹窗标题「修改期望到货区域」。左列表=全部JIT/定制品，右侧=已选，底部=区域单选+确认。

### 2. 每页改 500 条（减少翻页）

底部「共有 N 条 每页 50」行（y≈1196）→ 点「50」下拉（参考 (940,1196)）→
选项 50/100/200/500 纵排（间距≈42px）→ 点 500 → sleep 4 确认「共有 N 条 每页 500」。

### 3. 分批全选（每页 500 = 一批，用户已认可分批提交）

- 表头复选框（参考 (525,776)）：**只全选当前页**（与文档"一键全选"不同！）。
- 每轮：点表头 → sleep 3 → OCR 计数「已选中 X 个」→ 必须比上轮**增加**该页行数；
  不增长 → sleep 3 重读一次 → 仍不增长 → **停手报告**（勿盲目重试，防连点误触）。
- 勾满一批（一页）就提交一批，不必攒全部（页间勾选曾出现丢失，分批更稳）。

### 4. 提交一批

- 底部区域单选：广东≈(1098,1342) / **义乌≈(1214,1344)** / 按照…推荐≈(1330,1342)；
  点完裁剪放大验证义乌单选变蓝。
- 点「确认」（参考 (1684,1345)）→ 弹「确认将 N 个JIT商品/定制品的期望到货区域修改为义乌？」→
  点弹窗内蓝色「确认」（参考 (1457,859)，OCR 读不出白字就按坐标+裁剪验证）。
- 提交后底部按钮变灰=处理中；**等弹窗自行关闭**（约 10-15s）即成功，勿重复点击。

### 5. 收尾验证（必做）

重开弹窗，用「当前期望到货区域」多选下拉（参考 (1250,600)，选项从上到下
全选/广东/义乌/按照历史发货地就近推荐，间距≈42px）逐个筛选 + 查询（(748,684)）：

- 「按照历史发货地就近推荐」应 = 0
- 「广东」应 = 0
- 「义乌」应 = 总条数（如 2396）

任一不为 0 → 回到步骤 3 继续处理该批；全部为 0 → 点「退出」关弹窗。

### 6. 报告

`write_report("expect-region", ok, lines)`：店铺账号名 / 提交批次与每批数量 /
三个筛选的最终计数 / 未碰同步按钮与验证码声明。

## 坑速查

| 症状 | 处理 |
|---|---|
| 表头勾选后计数不涨 | 页面还在加载 500 行，等 3-5s 再读；连续 2 次失败停手 |
| 每页下拉点不开 | y 坐标取 OCR 行中心（≈1196），勿用目测 |
| 「确认」点了没反应 | 先看是否弹了二次确认层；再确认按钮是否已变灰（处理中） |
| 弹窗内分页按钮位置变动 | 每轮 OCR 重新定位，勿复用上轮坐标 |
| 500 行渲染慢 | 每次翻页/勾选后 sleep ≥3s，宁可慢不可错 |
