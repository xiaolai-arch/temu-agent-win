## 四、执行方式（已验证流程 + 本晚大修后的 grind_one.py）

```
cd D:\temu-agent\driver
python grind_one.py <SKC-ID> <类目:派对餐巾|身份腕带|餐巾> <标题关键词(可省，主判据是SKC-ID)>
```
- 流程：一键已读消息 → 上新生命周期页 → 商品ID查询(SKC) → 收集发起调价链接 →
  **逐链接：点开→等「确认调价」蓝块出现（弹窗渲染门控）→ 弹窗头部 SKC-ID 数字匹配**
  （标题关键词仅兜底）→ 扫描登记待填行（自下而上取消勾选作废/达标行）→
  **逐行填写：每次填前重新 OCR 定位（锚定「请输入」占位符）+ 数量二次 OCR 交叉验证
  取位数多者 + 填完立即验证（数值或绿色「降价」标签）**→ 确认调价 →
  **失败自动自救（像素级扫红提示条带取消空勾选行）后重试**→ 弹窗关闭=成功
- 三条铁律不变：①勾选行必须填值 ②成功唯一信号=弹窗关闭 ③最终以导出复核为准
- 已知残留问题：
  - 部分 SKU 规格 OCR 识别不出（如 48件/17pcs）→ 行被跳过、提交前被自救取消勾选，
    保持原价不受伤（21180329924 的 48件 38.32 仍保本，可下轮再试）
  - 「152pcs→52件」类丢首位数字已加交叉验证，但建议抽查高价行
  - 弹窗首个链接常渲染不全（穿透底层页），脚本自动跳过点第二个（同一按钮）
